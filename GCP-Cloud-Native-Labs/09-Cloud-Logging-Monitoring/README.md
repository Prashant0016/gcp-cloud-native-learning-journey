# Task 9 – Cloud Logging, Monitoring & Troubleshooting

## Objective

Explore Linux and cloud logging fundamentals by collecting system logs, monitoring NGINX activity, and understanding how cloud engineers troubleshoot production systems using logs and metrics.

## Real-World Scenario

A production application suddenly becomes:
- Slow
- Unavailable
- Unresponsive
- Frequently crashes
- Returns unexpected errors

Rather than restarting infrastructure immediately, cloud engineers first investigate the issue by:
- Reviewing logs
- Monitoring system metrics
- Identifying the root cause
- Troubleshooting systematically

Observability is a critical part of maintaining reliable cloud applications.

- Compute Engine

## Implementation Steps

### Step 1 – Create a Virtual Machine

Create a new Ubuntu Virtual Machine.
- Configure the desired machine name.
- Allow **HTTP Traffic**.

Connect to the VM using SSH.

### Step 2 – Install NGINX

Update the package repository | sudo apt update

Install NGINX | sudo apt install nginx -y

Start the web server | sudo systemctl start nginx

Open the VM's External IP address in a web browser to verify that the NGINX Welcome Page is accessible.

### Step 3 – Explore the Log Directory

Navigate to the Linux log directory | cd /var/log

List the available log files | ls

Observe the various system and application log files generated by Linux services.

### Step 4 – View System Logs

Display the most recent system log entries | sudo tail /var/log/syslog

These logs contain operating system events, service activity, warnings, and other system-level information.

### Step 5 – Monitor NGINX Access Logs

Watch incoming web requests in real time | sudo tail -f /var/log/nginx/access.log

Open or refresh the NGINX webpage in a browser and observe new log entries appearing automatically. Press **Ctrl + C** to stop live monitoring.

### Step 6 – View NGINX Error Logs

Display the NGINX error log | sudo tail /var/log/nginx/error.log

Review any recorded warnings or application errors.

## Key Concepts Learned

### Logging

Logging is the process of recording events generated by applications and operating systems. Examples include:
- User logins
- Service startup
- Application requests
- Errors
- System crashes

Logs provide a historical record that helps engineers investigate issues after they occur.

### Monitoring

Monitoring is the continuous observation of system health and performance. Common monitoring metrics include:
- CPU utilization
- Memory usage
- Network traffic
- System uptime
- Application availability

Monitoring helps identify performance issues before they affect users.

### Observability

Observability is the ability to understand the behavior and health of a system by analyzing:
- Logs
- Metrics
- Traces

Together, these sources help engineers identify and troubleshoot issues efficiently.

### Linux Log Directory

Most Linux systems store log files in: /var/log

Different applications and services generate their own log files within this directory.

### Syslog

Syslog is the primary Linux logging mechanism. It records:
- System events
- Service activity
- Kernel messages
- Warnings
- Errors

System administrators frequently consult Syslog when troubleshooting operating system issues.

### Tail Command

The `tail` command displays the most recent entries in a log file. Using: tail -f | 
enables real-time log monitoring by continuously displaying new log entries as they are written.

### Access Logs

Access logs record every incoming request received by the web server. Typical information includes:
- Visitor IP Address
- Requested URL
- Response Status Code
- Request Timestamp

These logs help analyze application traffic and user activity.

### Error Logs

Error logs record issues encountered by the web server. Examples include:
- Failed requests
- Configuration problems
- Application errors
- Server failures

Error logs are one of the primary resources used during troubleshooting.

### Cloud Logging

Google Cloud Logging is a managed logging service that centrally collects logs from Google Cloud resources. It can aggregate:
- Virtual Machine logs
- Application logs
- Audit logs
- Infrastructure events

Centralized logging simplifies monitoring and troubleshooting across cloud environments.

### Metrics

Metrics are numerical measurements collected over time that represent system performance. Examples include:
- CPU Utilization
- Memory Usage
- Requests per Second
- Disk Usage

Metrics provide a high-level view of system health and performance trends.

### Logs vs Metrics

| Logs | Metrics |
|------|---------|
| Detailed event records | Numerical measurements |
| Explain what happened | Show how the system is performing |
| Useful for troubleshooting | Useful for monitoring trends |

Together, logs and metrics provide comprehensive visibility into application and infrastructure health.
